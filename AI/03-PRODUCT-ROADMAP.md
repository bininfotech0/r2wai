# R2WAI 2.0 — Product Roadmap

## Launch objective

Deliver a commercially usable product around the complete journey:

```text
Connect → Discover → Build → Test → Publish → Monitor
```

## P0 — Build now

- Agent runtime
- Agent versioning
- Connection engine
- OpenAPI discovery
- Parameter resolution
- Tool registry
- Tool gateway
- Knowledge/RAG
- Agent Playground
- Agent Autopilot
- Publish
- Website Widget
- Activity
- Audit
- RBAC
- Policies
- Approvals
- Tenant/workspace isolation

## P1 — Build after core flow

- Additional curated providers
- Advanced automation capabilities
- Better evaluation
- Advanced analytics
- Additional publishing channels
- Enterprise lifecycle features

## Defer

- Huge connector marketplace
- Advanced visual workflow canvas
- Multi-agent orchestration as primary UX
- Knowledge graph
- Fine-tuning platform
- Model training
- GPU cluster management
- Multi-region
- Marketplace
- Large mobile channel ecosystem

## Do not make core

- Department hierarchy
- Application hierarchy
- Chatbot-only architecture
- AI model training platform
- Silent autonomous self-modification
- Customer-specific hardcoded application logic
- Fake analytics
- Unrestricted SQL
- Unrestricted HTTP
- Unrestricted filesystem access
- Unrestricted URL fetching

## Launch gates

A release should demonstrate:

1. Employee Assistant
2. API Agent
3. Website AI

All three must work end-to-end with real data paths.

## 90-day planning model

### Days 1–30
- Product freeze
- Repository audit
- Runtime gaps
- Connection engine
- API Autopilot
- Security baseline

### Days 31–60
- Knowledge pipeline
- Agent Autopilot
- Playground
- Publish / Widget
- Activity / Audit
- Premium UI

### Days 61–90
- Flagship demos
- Performance testing
- Security testing
- Documentation
- Pilot customers
- Pricing validation
- Launch website

These are planning targets, not claims that the repository is currently at any particular phase.
